# Arsitektur — Media Produk Universal (Foto Unggulan + Galeri)

> **Status: SELESAI & TERVERIFIKASI as-built (F1–F4, 2026-10-27) — SOURCE OF TRUTH media produk.** Bagian §1–§4 adalah rancangan asli; §5–§8 keadaan nyata. Pemicu: pemilik mengusulkan agar Haji, Umroh, Katering, dll. juga punya foto — lebih menarik secara UI — dengan foto dijadikan **komponen** yang dipakai di mana-mana (*featured image*); hanya Hotel dan Ziarah yang butuh galeri. Sejajar komponen universal lain (harga, dokumen, manifest, alamat, kontak, biaya, vendor).

## 1. Recheck (kode aktual, 2026-10-27)

| Entitas | Foto hari ini | Catatan |
|---|---|---|
| Hotel | `images Json` (galeri) + `featuredImageKey`; route `…/hotels/[id]/images` (GET/POST/DELETE); `ProductMediaGallery` | Satu-satunya yang punya "sampul" eksplisit |
| Kendaraan transport | `images Json`; route `…/vehicles/[id]/images`; `ProductMediaGallery`; katalog memakai foto pertama sebagai sampul | Galeri tanpa sampul eksplisit |

| Situs Wisata | `photoKey` tunggal; route `…/tourism-sites/[id]/photo` | |

**Masalah struktural:** empat implementasi salinan (tiga bentuk kolom berbeda: `images`, `images+featuredImageKey`, `photoKey`); tiap route mengulang validasi MIME/ukuran; **validasi hanya mempercayai `file.type` dari klien** (tak ada pemeriksaan isi/magic bytes — pelanggaran semangat "validasi server-side" di CLAUDE.md); setiap halaman publik membangun URL presigned sendiri (`getPresignedUrl(…, 3600)` per kartu, tanpa batch/cadangan visual); tak ada alt-text; menghapus produk tidak otomatis membersihkan objek MinIO (risiko yatim); tak ada ukuran turunan (gambar asli ≤5 MB dimuat di kartu). `lib/storage/minio-loader.ts` (loader `next/image` untuk gambar publik) ada tetapi tak dipakai — bucket private, jadi presigned.

## 2. Pendapat dan keputusan

**Ya, menarik dan layak** — katalog tanpa gambar terasa kosong; foto sampul adalah peningkatan UI dengan biaya terendah, dan karena kolom `images` Haji/Paket sudah mati, ini sekaligus membersihkan utang.

Keputusan (usulan, dapat diubah sebelum F1):
1. **Satu tabel polimorfik `ProductImage`** (`productType`, `productId`, `key`, `alt`, `sortOrder`, `isFeatured`, ukuran) — pola yang sama dengan `ProductCost`/`ManifestFieldRequirement`/`DocumentRequirement` — menggantikan semua kolom foto per-model. Alasan: satu implementasi, satu route, satu komponen, penghapusan produk membersihkan objeknya lewat registry pemilik.
2. **Dua mode per tipe lewat registry** (`lib/media/owners.ts`, sejajar `costComponentOwners`): `featured` (tepat satu foto) dan `gallery` (banyak, satu ditandai sampul, batas jumlah). Usulan: **gallery** = Hotel, Paket Ziarah; **featured** = Haji, Paket Umroh, Katering, Visa, Muthowif (foto profil), Situs Wisata; **Kendaraan** = *gallery* (sudah galeri; menurunkannya menghilangkan fitur — keputusan pemilik).
3. **Komponen admin tunggal `MediaField`** (`mode="featured" | "gallery"`) menggantikan `ProductMediaGallery` dan dua route foto tunggal; **komponen tampilan `ProductImage`** (+ helper server `getProductImages(type, ids)` batch) dengan *placeholder* ikon per tipe bila belum ada foto — sehingga katalog tak pernah "bolong".
4. **Satu jalur unggah**: `/api/v1/admin/media/[productType]/[productId]` (GET/POST/PATCH sampul-urutan-alt/DELETE), otorisasi `requireManager`, validasi **MIME dari isi file** (magic bytes JPEG/PNG/WebP) + ukuran + jumlah, kunci objek dibuat server (`{entity}/{id}/images/…`), DELETE hanya objek yang tercatat (SEC-62).
5. **Ukuran turunan** (revisi saat eksekusi F1): TIDAK menyimpan berkas asli — dua keluaran webp: tampilan (≤1600 px) dan kartu (≤640 px), keduanya dienkode ulang oleh `sharp` sehingga **EXIF/GPS dan muatan tersisip dibuang** (privasi + ukuran); presigned tetap (bucket private).
6. **Migrasi ekspansi–kontraksi** seperti vendor: F1 buat `product_images` + isi dari kolom lama (Hotel/Kendaraan/Muthowif/Situs; kunci objek MinIO dipertahankan, tanpa salin berkas); kolom lama dibuang di fase kontraksi. Data dev boleh hilang, tetapi arsitektur migrasinya tetap fail-closed dan teruji.
7. **Unggah saat membuat**: halaman `/new` tidak bisa mengunggah sebelum entitas ada; setelah simpan, pengguna masuk ke halaman edit yang menampilkan `MediaField` (sampul adalah langkah pertama di sana). Opsi "pilih berkas di halaman buat, unggah otomatis setelah simpan" dicatat sebagai peningkatan, bukan F1.

## 4. Risiko
- URL presigned kedaluwarsa (1 jam) pada halaman yang di-cache — katalog tetap dinamis; tak ada ISR untuk halaman bergambar.
- Menurunkan Kendaraan ke featured menghapus galeri — default usulan: dipertahankan galeri.
- Biaya CPU turunan ukuran saat unggah — dibatasi 5 MB per file dan satu file per permintaan.

## 5. As-built F1 (2026-10-27)

**Dibuat:** model `ProductImage` + migrasi ekspansi `20261027120000_product_images_expand` (isi dari `Hotel.images/featuredImageKey`, `TransportVehicle.images`, `Muthowif.photoKey`, `TourismSite.photoKey`; fail-closed: elemen bukan teks atau kunci objek ganda membatalkan seluruh migrasi); `lib/media/{owners,image,storage,service,urls,handlers,legacyRoutes}.ts`; route generik `/api/v1/admin/media/[productType]/[productId]` (GET/POST/PATCH urutan) dan `…/[imageId]` (PATCH alt/sampul, DELETE); `scripts/test-media.ts` + `scripts/test-media-migration.ts` (di rantai `bun run test`).
**Registry (`MEDIA_OWNERS`):** gallery — Hotel (12), Paket Ziarah (12), **Kendaraan (10, keputusan pemilik: tetap galeri)**; featured — Haji, Paket Umroh, Katering, Visa, Muthowif, Situs Wisata. Haji/Paket/Katering/Visa/Paket Ziarah sudah bisa diunggah lewat API; UI-nya F2, tampilan publiknya F3.
**Pemrosesan:** isi berkas diperiksa (magic bytes JPEG/PNG/WebP) lalu didekode sharp (batas 40 MP, `failOn: error`) — MIME dari klien tak dipercaya; keluaran webp tampilan + kartu, EXIF dibuang, orientasi diterapkan; maksimal 5 MB. Kunci objek dibuat server (`{tipe}/{id}/images/{ts}-{uuid8}-display|card.webp`); `DELETE` hanya objek yang tercatat pada produk itu (SEC-62); featured mengganti, gallery menegakkan max + tepat satu sampul (transaksi `Serializable`, konflik → 409); gagal simpan DB/penyimpanan membersihkan objek yang sudah terunggah.
**Jembatan sementara (dihapus di F2):** route lama `hotels/[id]/images`, `vehicles/[id]/images`, `muthowif/[id]/photo`, `tourism-sites/[id]/photo` kini penerjemah tipis ke layanan (bentuk respons lama dipertahankan untuk UI lama); `PUT hotel { featuredImageKey }` dan `GET hotel.featuredImageKey` diterjemahkan ke sampul layanan — TIDAK ada lagi penulisan kolom foto lama (tak ada dualisme). Semua pembaca publik (home, Hotel list/detail, Transport, Muthowif list/detail, Ziarah) dan API katalog (hotels, tour-packages, muthowif) membaca dari `getProductImages`/`getFeaturedCardUrls`; API katalog hotel tak lagi membocorkan kunci objek mentah (`coverUrl`/`imageUrls` presigned menggantikan `images`/`featuredImageKey`). Kolom lama masih ada (dibuang F4); `lib/haji/catalog.ts` masih memetakan kolom mati `images` sampai F3.
**Bukti:** (a) tes: 14 uji media (gambar sah/ditolak, EXIF, layanan pada DB sungguhan, handler, registry, penjaga sumber) dengan **6 mutasi tertangkap** (objek lama tak dihapus, batas dilepas, magic bytes dimatikan, hapus lintas produk, EXIF dipertahankan, PATCH longgar); 5 uji migrasi (data lama termasuk sampul di luar galeri/tanpa sampul, DB kosong, 2 skenario gagal-tertutup+atomik, tanpa drift) dengan **3 mutasi SQL tertangkap**. (b) **MinIO nyata** (dev lokal) lewat route nyata di Chrome: unggah PNG 2400×1600 → objek tampilan 1600×1067 webp (3 KB) dan kartu 640×427 terbaca dari URL presigned; sampul pindah; berkas PHP ber-MIME png → 400; tipe tak terdaftar/id bukan uuid → 404; jembatan lama (GET/POST/PUT featuredImageKey/DELETE kunci asing 404); katalog API + halaman publik hotel menampilkan gambar dari layanan; Haji unggah 2× → satu baris dan objek lama 404 (terhapus di MinIO); pembersihan lewat API menyisakan 0 baris/objek. `bun run test`, `bun run build` (salinan terpisah), `bun audit` hijau.
**Keterbatasan yang jujur:** (1) baris hasil migrasi lama menyimpan objek asli apa adanya (tanpa kartu/alt/EXIF dibuang) sampai diunggah ulang — kartu jatuh ke objek asli; (2) pembersihan objek saat PRODUK dihapus (`removeAll` sudah ada) belum dipasang di rute hapus produk — F4; (3) pengujian `Serializable` konflik bersamaan tidak disimulasikan (dijaga kode: P2034 → 409).

## 8. As-built F4 (2026-10-27) — kontraksi dan penutup

**Dibuat:** migrasi kontraksi `20261027180000_product_images_contract` — membuang 7 kolom foto per-model (`hotels.images/featuredImageKey`, `transport_vehicles.images`, `muthowif.photoKey`, `tourism_sites.photoKey`, `haji_products.images`, `packages.images`); **fail-closed**: dibatalkan (atomik) bila `product_images` belum ada; tanpa pengisian ulang (kolom lama beku sejak ekspansi — kunci yang tak ada di `product_images` berarti fotonya sudah dihapus lewat layanan; mengisi ulang akan menghidupkan kunci yatim). `purgeProductMedia(type, id)` di `lib/media/service.ts` (baris + objek MinIO; kegagalan dicatat tanpa menggagalkan penghapusan produk yang sudah berhasil) dipasang di **empat jalur hapus sungguhan**: Kendaraan, Katering, Haji, Visa. Pembuat produk (Haji, Hotel, Paket Umroh) dan `prisma/seed.ts` tak lagi menulis `images`. `scripts/test-media-contraction.ts` baru; uji drift skema penuh pindah ke sana (migrasi terbaru).
